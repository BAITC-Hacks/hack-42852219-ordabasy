# Аким на 5 часов

Симулятор управления городом: выберите пять мероприятий, распределите 100
условных единиц и сравните влияние решений на районы и Astana Quality of Life
Score. Расчёт полностью выполняется существующим Python/FastAPI backend.
Адаптивный интерфейс основан на предоставленном дизайне с картой районов.

Данные, границы районов и индекс синтетические. Это учебная модель для сравнения
сценариев, не официальная статистика и не прогноз развития Астаны.

## Быстрый запуск через Docker

Требования: Docker Engine/Desktop и Docker Compose v2. Все команды выполняются
из каталога `hack-42852219-ordabasy`.

```sh
docker compose up --build -d --wait backend
```

- Приложение: [localhost:8000](http://localhost:8000/).
- Swagger: [localhost:8000/docs](http://localhost:8000/docs).
- Health: [localhost:8000/api/health](http://localhost:8000/api/health).

`.env` и ключ OpenAI для запуска не требуются. Если порт 8000 занят:

```sh
APP_PORT=8001 docker compose up --build -d --wait backend
```

Тогда приложение откроется на `http://localhost:8001`. Внутри контейнера сервер
слушает `0.0.0.0:8000`, на компьютере порт по умолчанию опубликован только на
`127.0.0.1`. Frontend и backend находятся в одном контейнере и используют один
origin. БД, Redis, отдельный JS-сервер и Docker volumes не нужны.

```sh
docker compose logs --tail=100 backend
docker compose stop backend
```

Остановка не удаляет контейнеры или тома. Подробности: [Docker](docs/docker.md).

## Основной сценарий

1. Выберите район на карте, изучите его профиль и десять показателей.
2. Отфильтруйте каталог по направлению и откройте карточку инициативы.
3. Выберите целевой район; городские меры применяются сразу ко всем районам.
4. Соберите пять решений. Можно заменять мероприятия, менять район и удалять их.
   Недопустимая замена не изменяет сохранённый план.
5. Нажмите «Рассчитать сценарий». Получите Score, изменения по районам,
   критические показатели, эффект каждой меры и сработавшие синергии.

Кнопка «Эталонный план» загружает пример из задания. Она явно подтверждает замену
непустого плана. Черновик сохраняется в браузере и восстанавливается только при
совпадающей версии датасета и успешной проверке правил.

После редактирования предыдущий результат и AI-анализ сбрасываются. Ответы
старой версии сценария игнорируются. Карта, показатели и результат читают единый
серверный расчёт; UI не содержит собственной формулы Score.

## Правила модели

| Правило | Значение |
| --- | --- |
| Бюджет | 100 условных единиц, одинаковый для всех |
| Итоговый набор | Ровно 5 уникальных мер |
| Направления | Не более 2 мер на направление; минимум 3 направления |
| Горизонт | 8 кварталов |
| Реализованный эффект меры | Полный эффект × `(8 − лаг) / 8` |
| Показатели | 0–100, больше — лучше |
| Критический показатель | Строго меньше 40 |
| Остаток бюджета | Не добавляет баллы |

Не требуется по одному мероприятию каждого направления. Черновик из 0–4 мер
допустим, но финальный расчёт недоступен. Все цены и эффекты берутся из
серверного каталога; клиент не может задать собственный бюджет или Score.

Сначала суммируются все положительные и отрицательные эффекты и синергии, затем
каждый показатель один раз ограничивается диапазоном 0–100. После этого:

```text
D_d = сумма(вес показателя × его итоговое значение)
D_avg = сумма(доля населения района × D_d)
Score = 0.7 × D_avg + 0.3 × min(D_d) − N_crit
```

`N_crit` — число пар «район × показатель» ниже 40. Значение ровно 40 не
штрафуется. Округляется только отображение, до двух знаков. Сам Score не
ограничивается искусственно диапазоном 0–100: ограничиваются показатели.

| Показатели | T1 | T2 | E1 | E2 | S1 | S2 | B1 | B2 | C1 | C2 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Вес | .10 | .10 | .09 | .11 | .11 | .11 | .09 | .09 | .10 | .10 |

Пять сводных полос интерфейса — нормированные взвешенные средние соответствующих
пар показателей, а не дополнительные параметры модели.

Синергии фиксированные, лагом не уменьшаются:

- M1 + M2: T1 +2 в районе M1.
- M10 + M12: B1 +2 в районе M10.
- M5 + M6: E2 +2 в районе M5.

Несовместимости:

- M1 + M3 запрещены при любых районах.
- M4 + M7 запрещены только в одном районе.
- M5 + M13 запрещены только в одном районе.

Влияние мер на итоговый Score неаддитивно из-за минимума, штрафов, ограничения
показателей и синергий. На экране показываются реальные изменения показателей,
а не выдуманные независимые «баллы каждой меры».

## Архитектура и API

```text
web/                         HTML, CSS, ES-модули: карта, план, результаты
app/domain/engine.py          чистый Python: правила, валидация, расчёт
app/data/                    5 районов и 14 мероприятий в JSON
app/modules/simulations/     HTTP-схемы, адаптер движка, публичные маршруты
app/modules/districts/       существующий модуль каталога районов
app/modules/initiatives/     существующий модуль каталога мер
app/modules/analysis/        system prompt, вызов OpenAI, проверка чисел для /api/analysis
app/modules/ai_analysis/     сохранённый legacy-модуль (/api/v1/ai-analysis)
tests/                       тесты движка и HTTP API
tests/frontend/              тесты состояния интерфейса
examples/                    эталонный запрос и AI-контекст
```

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/bootstrap` | Датасет, правила, каталог и базовый результат |
| POST | `/api/validate` | Проверка черновика; `final: true` требует 5 решений |
| POST | `/api/simulate` | Проверка и полный окончательный расчёт |
| GET | `/api/config` | Только публичные настройки frontend |
| GET | `/api/health` | Работоспособность backend без зависимости от AI |
| POST | `/api/analysis` | AI-разбор сценария через OpenAI; 404, если не настроен |

Запрос расчёта содержит `scenarioVersion` (строка) и `decisions`: список объектов
`initiativeId` и `districtId`. У городской меры район null или отсутствует.
Неизвестные поля запрещены. Невалидный окончательный сценарий возвращает HTTP 422:
`error.code`, `error.message`, `error.details.errors` с кодами и русскими
сообщениями. `/validate` возвращает HTTP 200 с `valid`, `complete`, бюджетом и
ошибками — это проверка, а не сохранение сценария.

Существующие `/api/v1/districts`, `/initiatives`, `/health`,
`/simulations/validate` и `/simulations/calculate` сохранены. Схемы каталога и
расчёта мигрированы на новый датасет; старое тело `initiative_ids` больше не
поддерживает корректный районный сценарий. Это намеренное изменение контракта.

Движок не изменяет исходные данные и не хранит пользовательское состояние.
Повторный расчёт одного набора воспроизводим и не зависит от порядка мер.

## AI-анализ сценария

`/api/analysis` реализован в `app/modules/analysis/` по контракту из
[docs/ai-contract.md](docs/ai-contract.md). Обработчик вызывает
`SimulationService.analysis_context(request)`, который проверяет сценарий и
получает численные факты из единственного движка; готовые баллы из браузера не
принимаются. Эти факты ("evidence") передаются OpenAI (`response_format:
json_schema`, strict) с system-промптом, запрещающим пересчитывать Score или
выдумывать меры/районы/эффекты. Каждое число в ответе модели сверяется с
evidence; при несовпадении запрос повторяется один раз с уточнением, а если
числа всё ещё не совпадают — возвращается ошибка `analysis_unavailable` (502).
Общая схема ответа — `AnalysisResponse`; `scenarioVersion` в ответе всегда
берётся backend'ом из evidence, а не от модели.

Режимы `APP_ANALYSIS_MODE`:

- `remote` (по умолчанию): реальный запрос к OpenAI. Без `OPENAI_API_KEY`
  маршрут отвечает 404 — UI показывает сообщение о недоступности и кнопку
  повтора, Score остаётся доступен.
- `mock`: явно обозначенный демонстрационный разбор по шаблону, без обращения к LLM.
- `disabled`: AI отключён, все расчётные функции доступны.

Модуль `app/modules/ai_analysis/` не переписывался. Его старый endpoint
`/api/v1/ai-analysis` не связан с новым `/api/analysis` и возвращает
контролируемую ошибку `legacy_request`.

Ключ `OPENAI_API_KEY` и модель `APP_OPENAI_MODEL` передаются только backend во
время запуска. Ключ не нужен для расчёта и не включается в образ, Git,
frontend, публичную конфигурацию или ответы API. `.env.example` содержит
пустой шаблон; реальный `.env` игнорируется.

## Отдельный frontend и CORS

Обычный Docker-запуск уже обслуживает UI и API вместе, по относительному `/api`.
`APP_PUBLIC_API_BASE_URL` меняет публичный адрес API, который получает браузер.

Если `web/` размещён на другом origin, задайте в его `index.html` метатег
`api-base-url` со значением `http://localhost:8000/api`. Он определяет адрес
первоначального `/config` и имеет приоритет над относительным адресом из backend.
Добавьте фактический origin frontend в `APP_CORS_ORIGINS` (JSON-массив). По
умолчанию разрешены localhost/127.0.0.1 на портах 3000 и 5173.

`http://backend:8000` — адрес для других контейнеров в Docker-сети, не для
браузера пользователя. Используйте опубликованный порт localhost или реальный
доступный браузеру адрес сервера. При размещении на другом компьютере localhost
в браузере обозначает компьютер пользователя.

## Локальная разработка и тесты

Python 3.12. Для frontend-тестов дополнительно нужен Node.js 20+; самому
приложению Node/npm не требуются. Установка закреплённых зависимостей:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

На Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`.
Frontend использует нативные ES-модули и локальные SVG/CSS без внешних CDN;
после редактирования обновите страницу браузера.

```sh
.venv/bin/python -m pytest
node --test tests/frontend/*.test.mjs
docker compose --profile test run --build --rm tests
```

Проверяются эталонная арифметика, порог 40, бюджет, конфликты, синергии,
ограничение показателей после суммирования, перестановки мер, отсутствие мутаций,
контракты API, неподменяемость цены/Score, CORS, доставка интерфейса, ошибки AI и
атомарное редактирование черновика. Production-образ не содержит pytest.

Зависимости и базовый Docker-образ закреплены. Обновляйте `requirements.txt` и
`requirements-dev.txt` согласованно с `pyproject.toml` и повторяйте проверки.

Использованные механизмы: [StaticFiles FastAPI](https://fastapi.tiangolo.com/tutorial/static-files/),
[CORS FastAPI](https://fastapi.tiangolo.com/tutorial/cors/),
[Docker Compose](https://docs.docker.com/reference/compose-file/services/).
